# skyrim-cpp

**The Elder Scrolls V: Skyrim, ported to modern C++20 one system at a time.**

Skyrim is well over a decade old and still runs on a 32-bit engine built for a
console generation that is long gone. This project rebuilds it as clean,
portable C++20 that reads your own copy of the game and draws the world with
code written from scratch. It is a port, not a mod: no injected DLLs, no patched
executable, and no hooks into the original binary.

You can already stand on the ground at Helgen and look out over the streamed
exterior — terrain, buildings and rocks read straight from your own archives,
lit and textured by this engine. The RPG, the people and the quests are still to
come.

## What works today

**The world**
- Skyrim's cell tree is rebuilt from the original `.esm`/`.esp` masters: 17,612
  cells across 40 worldspaces and 703,934 placed references, read straight from
  the record tree, including zlib-compressed cells.
- Assets come out of the game's own `.bsa` archives. The reader is seek-based,
  so a 1.4 GB archive is never loaded whole.
- Meshes are parsed at runtime from the original `.nif` files: Skyrim LE
  geometry (`NiTriShape` / `NiTriStrips`), positions, normals, UVs, strips,
  diffuse textures and alpha-cutout flags. One reference mesh matches the
  community converter exactly at 13,329 verts / 9,524 tris / 12 groups.
- Textures are decoded from the original `.dds` files (BC1/BC2/BC3 and
  uncompressed) straight to the GPU.
- Exterior terrain is built from the original `LAND` records: the 33×33 vertex
  heightmap is reconstructed from its difference encoding and textured by the
  cell's own land textures, so you walk on the real ground rather than on boxes.
- The exterior world streams around you a cell at a time as you move.

**Rendering and playing**
- A Direct3D 9 host: lit and textured surfaces, alpha cutout for foliage and
  fences, and a GPU cache for meshes and textures.
- A first-person controller with gravity, jumping and step-up, plus a free-fly
  mode for looking around. You stand on the terrain heightmap and collide with
  the placed geometry as it streams in.
- English string tables (`.STRINGS`) resolve the game's names.

**Launcher**
- On first run it finds your Skyrim install by itself and remembers it, so you
  only point at it once.

## No game assets

This repository contains **source code only**. It ships no models, textures,
audio, scripts or text from Skyrim, and it never will. The player's own game
files are read at runtime; the program cannot run without a legal copy of the
game. The `tests/` fixtures are synthetic data generated by this repository's
own scripts — they contain nothing from Bethesda.

## Layout

```
skyrim-cpp/
├── include/skyrim/   Public API of the portable library (namespace skyrim)
├── src/world/        Library implementation: archives, records, cells, meshes
├── host/engine/      skyrim_standalone: window, renderer, player, collision
├── scripts/          progress.py refreshes the progress bar from ROADMAP.md
└── ROADMAP.md        Every milestone with its status
```

The project is split in two on purpose:

- **`skyrim_module`** is a static library. It reads the archives, records, cells
  and meshes, and has no `main()`, no renderer, no `<windows.h>` and no
  dependencies outside the C++ standard library. It builds on Windows, Linux and
  macOS.
- **`skyrim_standalone`** is the playable program built on that library. It owns
  the window, renderer, player and collision. Direct3D 9 and Win32 live only
  here, which keeps the library free to be driven by a different renderer.

## Building

You need CMake 3.20 or newer and a C++20 compiler (MSVC 2022, GCC 11+ or
Clang 14+). Builds are 64-bit, and a Release build compiles with zero warnings.
Python 3 is needed only to generate the test fixtures.

```sh
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release
```

On Linux and macOS this builds the library on its own. On Windows it also builds
`skyrim_standalone`, the playable program.

## Running

Just run it:

```sh
build\Release\skyrim_standalone --play
```

The first time, it looks for your Skyrim install. It checks `--data`/`--game`,
the saved setting, the `SKYRIM_DIR` and `SKYRIM_DATA_DIR` environment variables,
the program's own folder (so you can drop the build into your game folder), and
the usual Steam libraries. If it still can't find the game, it opens a folder
picker. The choice is saved in `skyrim_cpp.ini` next to the program, so you only
do this once.

Today it reads your install in place. Importing your data into the program's own
folder, so the original install can be deleted, is on the roadmap.

Useful flags:

| Flag | What it does |
|---|---|
| `--play` | Launch the windowed world |
| `--data DIR` / `--game DIR` | Use the Skyrim install in DIR |
| `--ws HEX` | Worldspace FormID to start in (default `3C`, Tamriel) |
| `--grid X Y` | Starting exterior cell (e.g. `4 -20` for Helgen) |
| `--radius N` | Cells streamed around the player (default 1, i.e. 3×3) |
| `--meshes BSA` | Archive to read meshes/textures from (repeatable) |
| `--width W` / `--height H` | Window size |
| `--frames N` | Render N frames then exit (headless smoke test) |
| `--types` / `--limit N` | Dump the record-type histogram / cap loaded records |

**Controls:** WASD to move, the mouse to look, Shift to run, Space to jump (or
rise when flying), Ctrl to descend, `F` to switch between walking and flying, and
`Esc` to quit.

## Contributing

Pull requests are welcome, from one-line fixes to whole subsystems.

- Pick an open item from [ROADMAP.md](ROADMAP.md), or open an issue for a bug you
  can reproduce. A cell coordinate and a screenshot help a lot.
- Follow the house style: `namespace skyrim`, snake_case file names in the
  library, `m_` prefixes for members, and standard C++20 with no compiler
  extensions.
- Keep the library portable. Platform and graphics code belongs in `host/`.
- A Release build must stay at zero warnings.
- Never commit game files or anything extracted from them, and never commit
  binaries. Test fixtures are generated at build time from `tests/make_*.py`.
- The container-format findings the readers are built on are recorded in
  [`docs/formats.md`](docs/formats.md).
- When a milestone changes, update `ROADMAP.md` and run
  `python scripts/progress.py` so the progress bar stays accurate.
